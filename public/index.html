1. What JSON is

        

          JSON (JavaScript Object Notation) is a text format for structured data. It was derived from
          JavaScript object syntax but is language-independent — every mainstream language can read and write it.
          A JSON document is a single value: usually an object { } or an array [ ].
        


        
The six data types

        

          
TypeExampleNotes

          
            
string"Functional QA"Double quotes only, Unicode, \n escapes

            
number42, 3.14, 1e6No NaN, no Infinity, no leading +

            
booleantrue, falseLowercase only

            
nullnullExplicitly "no value"

            
object{ "city": "Hyderabad" }Unordered key/value pairs, keys must be strings

            
array[1, 2, 3]Ordered, may mix types

          
        


        
A complete example

        

          
          
{
  "id": 31840000018316618,
  "title": "Functional QA",
  "remote": false,
  "city": "Hyderabad",
  "salary": null,
  "skills": ["manual testing", "SQL", "API testing"],
  "postedAt": "2026-08-04T18:30:00Z",
  "company": {
    "name": "Kumaran Systems",
    "url": "https://careers.kumaran.com"
  }
}

        


        
Rules that trip people up

        
    
          
  • No trailing commas, no comments, no single quotes.
    • 
          
  • Keys are always quoted strings — { city: "x" } is JavaScript, not JSON.
    • 
          
  • Dates are not a type. Teams encode them as ISO 8601 strings ("2026-08-04T18:30:00Z") or epoch numbers.
    • 
          
  • Large integers lose precision in JavaScript beyond 253; send IDs as strings when that matters.
    • 
          
  • Object key order is not guaranteed to be meaningful — never rely on it.
    • 
        

      


      

        
2. JSON across the stack

        
JSON is usually the common currency between every layer. A single request typically crosses it several times:

        

          Browser
          →
          API gateway
          →
          Service
          →
          Database
          →
          Logs / queue
        


        
Front end

        

          
          
const res = await fetch('/api/jobs?city=Hyderabad', {
  headers: { Accept: 'application/json' }
});
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const data = await res.json();   // parsed into JS objects

        


        
Back end

        

          Frameworks serialize objects to JSON on the way out and deserialize on the way in — Express
          res.json(), FastAPI/Pydantic models, Spring Jackson, Rails render json:.
          The important work is the contract, not the serializer.
        


        
Database

        

          PostgreSQL jsonb, MySQL JSON, MongoDB (BSON) and DynamoDB all store documents
          natively and let you index inside them. Use it for genuinely variable data; keep the fields you filter and
          join on as real columns.
        


        
Embedded in HTML

        

          Server-rendered pages ship data to the client inside the markup — application/ld+json for
          search engines, application/json for hydration (__NEXT_DATA__). That is precisely
          what the Home tool on this site extracts.
        

      


      

        
3. How JSON is developed in real applications


        
Design the contract first

        

          Teams agree the shape before writing code, usually as an OpenAPI spec or JSON Schema kept in version
          control. Both client and server then generate types from that single source of truth.
        


        
Use a response envelope

        

          
          
{
  "data": [ { "id": "1", "title": "Functional QA" } ],
  "meta": { "page": 1, "perPage": 20, "total": 137 },
  "errors": []
}

        

        
A stable wrapper means clients can add pagination or warnings later without a breaking change.


        
Validate at the boundary

        

          Never trust incoming JSON. Validate against a schema on arrival — jsonschema or Pydantic in
          Python, Zod or Ajv in JavaScript — and reject early with a clear error.
        

        

          
          
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "required": ["id", "title"],
  "properties": {
    "id":     { "type": "string" },
    "title":  { "type": "string", "minLength": 1 },
    "remote": { "type": "boolean", "default": false },
    "skills": { "type": "array", "items": { "type": "string" } }
  },
  "additionalProperties": false
}

        


        
Conventions that age well

        
    
          
  • Pick one casing — camelCase or snake_case — and apply it everywhere.
    • 
          
  • Adding a field is backward compatible; renaming or removing one is not. Version the endpoint instead.
    • 
          
  • Prefer null over omitting a key when "unknown" is meaningful.
    • 
          
  • Return errors as structured objects (code, message, field), not bare strings.
    • 
          
  • Log as JSON lines so logs are queryable rather than grep-able.
    • 
        

      


      

        
4. Where JSON is mostly used

        

          
REST & GraphQL APIs
The default request and response format for web and mobile clients.

          
Configuration
package.json, tsconfig.json, cloud IAM policies, CI definitions.

          
Structured data / SEO
JSON-LD in <script type="application/ld+json"> describing articles, jobs and products.

          
Page hydration
Server-rendered state handed to the browser as an embedded JSON blob.

          
Messaging
Kafka, RabbitMQ and webhook payloads between services.

          
Document stores
MongoDB, PostgreSQL jsonb, Elasticsearch documents.

          
Observability
Structured logs, traces and metrics shipped as JSON lines.

          
Data exchange
Exports, ETL hand-offs and ML feature payloads.

        

        

          Where JSON is a poor fit: very large tabular datasets (use Parquet), binary content, and ultra
          low-latency internal RPC (use Protobuf or Avro).

6. Create and test a JSON fetch in Python

        
Everything below uses the standard library first, so it runs on a clean Python 3.9+ install.


        
Step 1 — Create JSON from Python objects

        

          
          
import json

job = {
    "id": "31840000018316618",
    "title": "Functional QA",
    "remote": False,          # becomes false
    "salary": None,           # becomes null
    "skills": ["manual testing", "SQL"],
}

text = json.dumps(job, indent=2, ensure_ascii=False)
print(text)

with open("job.json", "w", encoding="utf-8") as f:
    json.dump(job, f, indent=2)

        


        
Step 2 — Read it back

        

          
          
with open("job.json", encoding="utf-8") as f:
    data = json.load(f)

print(data["title"])              # Functional QA
print(data.get("salary", "n/a"))  # None
print(len(data["skills"]))        # 2

        


        
Step 3 — Fetch JSON from an API (standard library)

        

          
          
import json
import urllib.request
import urllib.error


def fetch_json(url: str, timeout: int = 10) -> dict:
    """Fetch a URL and parse the response as JSON."""
    request = urllib.request.Request(
        url,
        headers={"Accept": "application/json", "User-Agent": "learn-json/1.0"},
    )
    try:
        with urllib.request.urlopen(request, timeout=timeout) as response:
            if response.status != 200:
                raise RuntimeError(f"HTTP {response.status}")
            charset = response.headers.get_content_charset() or "utf-8"
            return json.loads(response.read().decode(charset))
    except urllib.error.HTTPError as err:
        raise RuntimeError(f"HTTP {err.code} from {url}") from err
    except json.JSONDecodeError as err:
        raise ValueError(f"Response was not valid JSON: {err}") from err


if __name__ == "__main__":
    data = fetch_json("https://api.github.com/repos/python/cpython")
    print(data["full_name"], "-", data["stargazers_count"], "stars")

Step 5 — Pull embedded JSON out of a web page

        
This is the Python equivalent of what this site's scraper does in static mode:

        

          
          
# pip install requests beautifulsoup4
import json
import requests
from bs4 import BeautifulSoup

html = requests.get("https://en.wikipedia.org/wiki/JSON", timeout=10).text
soup = BeautifulSoup(html, "html.parser")

blocks = []
for tag in soup.select('script[type="application/ld+json"], script[type="application/json"]'):
    if not tag.string:
        continue
    try:
        blocks.append(json.loads(tag.string))
    except json.JSONDecodeError:
        continue   # some sites emit almost-JSON

for block in blocks:
    print(block.get("@type"), "-", block.get("datePublished"))

        


        
Step 6 — Test it

        
Tests should not hit the network. Stub the fetch and assert on the parsing:

        

          
          
# pip install pytest
# test_fetch_json.py
import json
import pytest
from fetch_json import fetch_json


class FakeResponse:
    def __init__(self, payload, status=200):
        self._body = json.dumps(payload).encode()
        self.status = status
        self.headers = type("H", (), {"get_content_charset": lambda self: "utf-8"})()

    def read(self):
        return self._body

    def __enter__(self):
        return self

    def __exit__(self, *args):
        return False


def test_parses_json(monkeypatch):
    monkeypatch.setattr(
        "urllib.request.urlopen",
        lambda *a, **k: FakeResponse({"title": "Functional QA"}),
    )
    assert fetch_json("https://example.com/job")["title"] == "Functional QA"


def test_rejects_invalid_json(monkeypatch):
    bad = FakeResponse({})
    bad._body = b"{ not json }"
    monkeypatch.setattr("urllib.request.urlopen", lambda *a, **k: bad)

    with pytest.raises(ValueError):
        fetch_json("https://example.com/job")

        

        

          
          
pytest -q          # run the tests
python -m json.tool job.json   # validate any JSON file from the shell

        


        
Common Python gotchas

        
    
          
  • json.dumps fails on datetime and Decimal — pass default=str or a custom encoder.
    • 
          
  • Python allows NaN and Infinity by default; use allow_nan=False for interoperable output.
    • 
          
  • Object keys become strings: {1: "a"} round-trips as {"1": "a"}.
    • 
          
  • Always pass a timeout — a hung request otherwise blocks forever.
    • 
        

      

    


    

      

        
About

        
About JSON Scraper

        
Why this tool exists and how it works.

      

      

        
What it does

        

          JSON Scraper extracts embedded JSON — application/ld+json, application/json,
          and JavaScript globals such as __NEXT_DATA__ — from any public web page, then lists every
          distinct field with its XPath so you can copy exactly what you need.
        


        
Why a server does the fetching

        

          The equivalent DevTools snippet cannot be automated from a web page: the browser's same-origin policy
          blocks reading another site's HTML. Requests are therefore made server-side, where that restriction does
          not apply, so target-site CORS never blocks a lookup.
        


        
Two fetch strategies

        
    
          
  • Static — a plain HTTP fetch, for server-rendered pages.
    • 
          
  • Browser — Chromium renders the page, then the extraction snippet runs in the page context, for single-page apps.
    • 
          
  • Auto — static first, falling back to the browser only when nothing was parsed.
    • 
        


        
Built with

        
Node.js, Playwright and Cheerio, with no front-end framework.
